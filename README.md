# 신통사주카페 예약 사이트 (초기 시제품)

## 우선 실행하기
`index.html`을 브라우저로 열면 **체험 모드**로 동작합니다. 같은 브라우저의 localStorage에만 데이터가 저장되며, 다른 고객의 휴대폰과 예약은 연동되지 않습니다.
관리자 체험: `admin@demo.local` / `123456` (**체험용으로만 사용**)

1. 관리자 화면에서 체험 계정으로 로그인합니다.
2. `날짜별 영업시간`에서 날짜, 휴무/방문/전화/모두, 시간, 예약 간격, 여유시간을 지정합니다.
3. 고객용 `상담 예약`에서 예약하고, 관리자 화면에서 승인합니다.
4. `전화 예약 직접 등록`도 가능합니다.

## 실제 서비스를 위한 준비
**현 소스는 배포 전 보안 보강이 필요한 시제품입니다.** 개인정보를 받는 실서비스로 그대로 공개하지 마세요.
- Firebase 프로젝트 생성, Firestore 및 Email/Password Authentication 활성화, 관리자 사용자 생성
- `index.html`의 `FIREBASE_CONFIG` 값을 실제 Firebase 웹 앱 설정으로 변경
- `firestore.rules`의 `REPLACE_WITH_ADMIN_EMAIL`을 관리자 로그인 이메일로 변경 후 Firebase 콘솔에 적용
- 현재 규칙에서는 공개 예약 조회가 불가능합니다. 예약조회는 Firebase Cloud Functions 같은 백엔드에서 전화번호+접수번호를 검증한 뒤 최소 정보만 반환하도록 구현해야 합니다.
- 현재 규칙은 익명 사용자에 의한 예약·잠금 조작 가능성, 서비스 남용/스팸, 임의 슬롯 락 생성 가능성이 있어 실제 배포 시 서버 검증, App Check, 요청 제한, 자동 만료/정리 등 보강이 필요합니다.
- Firestore 로그인 사용자에게만 예약 읽기 권한을 주지만 관리자 이메일만 확인하는 방식은 커스텀 클레임 또는 서버 권한 확인으로 강화하는 것이 좋습니다.
- 운영환경에서 Firestore 직접 예약 등록은 보안 규칙상 관리자 수동 예약과 공개 예약 신청의 데이터 조건이 달라 관리자 수동 등록이 작동하지 않습니다. 해당 기능은 서버 함수 또는 관리자용 별도 쓰기 경로로 구현해야 합니다.
- 현재 공개 앱은 설정 전체 조회, 잠금 조회를 통해 점유 시간을 렌더링합니다. 서버에서 예약 가능 시간 목록만 반환하는 방식이 더 안전합니다.
- 연락처 등 개인정보의 보관 기간, 파기 절차, 개인정보 처리방침과 접근권한을 준비하세요.

## 구성
- `index.html`: 모바일 반응형 고객/관리자 화면
- `firestore.rules`: Firebase 보안 규칙의 *초안*, 실서비스 사용 전 수정 필수

## v1.1 추가 기능 (2026-11-17)
- 관리자 로그인 후 첫 화면: **1주일 예약 시간표**. 월~일 7개 열을 날짜별 예약 시작시간 기준으로 표시합니다.
- `지난주`, `이번 주`, `다음 주` 버튼으로 주간 이동. 날짜 제목을 누르면 해당 날짜의 영업시간 설정으로 이동합니다.
- 상태별 색상: 초록 예약 가능, 파랑 확정, 노랑 승인 대기(시간 잠금), 회색 휴무/시간 외.
- 기존 v1의 로컬 저장 키(`sintong-demo-v1`)를 유지해 같은 브라우저에서는 기존 일정·예약 데이터를 그대로 사용합니다.
- 고객 예약 화면에서는 **승인 대기와 확정 예약 둘 다** `🔒 예약마감` 표시로 비활성화합니다. 예약을 거절/취소하면 다시 예약 가능해집니다.

**주의:** 체험 모드는 같은 브라우저에만 저장되어 여러 고객의 실제 휴대폰 사이에서 잠금이 공유되지 않습니다. 실제 공용 예약 링크를 운영하려면 Firebase 연결과 안전한 백엔드 검증·권한 제어·예약 조회 API를 갖춰야 합니다. 공개 실서비스에서는 Firestore 규칙 초안을 그대로 배포하지 마세요.
